### 0.2 【阻断级】任务书 §3.1 给出的换算公式，在本池上**无法按原样计算**

任务书原文 `[引用]`：
```

```

本池（P6 冻结导出）的字段实况 `[代码可读，见 §4.1]`：每个候选只有
`(op, target, confidence, evidence_spans, tenant, gold_error, gold_source)`——
**无 `n_new_entities`、无 `n_new_relations`、无 `text` 字段**。

**降级后的可用形式（本草案采用，并如实标注为降级）**：
```
minutes(s) = α · [op == CLS_ADD] + β · [op == REL_ADD]        （γ ≡ 0，因池内无文本字段）
```

- `[op == CLS_ADD]` ∈ {0,1}，`[op == REL_ADD]` ∈ {0,1}（Iverson 括号）。
- **γ 项被删除，不是取 0 了事**：这是**数据缺口**，必须在产物 JSON 里显式记为 `minutes_model_degraded: true, dropped_term: "gamma*len(text)/1000", reason: "pool has no text field"`。

### 2.2 计算口径（逐字抄自 `_k0_metrics_from_snapshot`，`[代码可读]`，函数签名 `(snapshot, seed_terms=None)`）

```
classes = snapshot["classes"];  n = len(classes)
若 n == 0 → 直接返回 {"cov":0.0, "red":0.0, "dep":0, "align":0.0}

cov  = (# 满足 ∃t∈seed_terms: c.name ∈ t 的类) / n
        ⚠️ seed_terms 为 None/空时 cov ≡ 0.0（代码分支：else: cov = 0.0）
red  = (Σ_c max(0, len(parents_c) - 1)) / n      parents_c = [parent] + ([also_parent] if 有)
dep  = max_c( 从 c 沿 parent 上溯的链长 )        root=1，遇环或缺失父即停；**返回整数**
align= (# 有 anchor 字段的类) / n
返回 {"cov": round(cov,4), "red": round(red,4), "dep": dep, "align": round(align,4)}
```

**三个必须披露的实现事实** `[代码可读]`：

1. **`Quality(·)` 只读 `snapshot["classes"]`，完全不读 `rel_types`。**
   ⇒ 本池 21 项中的 **10 个 `REL_ADD` 项对该函数贡献恒为 0**。这是 §4.3 结构零的另一半原因。
2. **`dep` 返回整数**（不是比例）。与 cov/red/align 三个比例**量纲不同**，不能直接加权求和。**必须显式归一化**（见 §2.3）。
3. **`cov` 依赖外部 `seed_terms`**。池内不含该字段 ⇒ 若不注入 seed_terms，`cov` 恒为 0.0，四指标实际退化为三个。

### 2.3 聚合方式（**必须写死，并说明为什么**）

**选定：向量式「全项不劣」判据（Pareto-dominance 的保守式）**

```
定义 Quality(Ω) = (cov(Ω), red(Ω), dep(Ω), align(Ω))
定义 Ω ⊨ Q*  ⟺  cov ≥ cov*  且  red ≤ red*  且  dep ≥ dep*  且  align ≥ align*
```

**为什么选它（三条理由，弃用备选的对照）**：

- **弃「加权和」**：四指标方向不一致（`red` 越小越好，其余越大越好），加权和需先翻转符号 + 自定权重 `w`。**权重是自由参数，事后可调 → 正是 P6 的教训（事后调 Q\*）的温床。**故拒绝。
- **弃「单一标量」**：官方评分句要的是「达到**同等**本体质量」，语义是「不劣于基准」，天然是**逐项不劣**，不是"总分相等"。
- **选「全项不劣」的代价必须披露**：这是**保守**判据 → 更难满足 → **两臂的分钟数都会变大**。但该保守性**对两臂对称**，因此**不偏袒任一臂**，不构成偏倚。

**选定：`Q* ≡ Quality(snapshot v1.1.0)`，即 as-built 已提交快照的四指标向量。**

### 3.4 敏感性分析（α、β 各 ±50%）

由 §4.0.2 的线性降级模型，两臂累计分钟数均为 `α·(#类) + β·(#关系)`：

```
若两臂审的项构成相同（§4.3 将证明前 10 项相同）：
  Δ = minutes(B) − minutes(A) = α·Δn_cls + β·Δn_rel
  α = (1+t)·α₀, β = (1+t)·β₀, t ∈ {−0.5, 0, +0.5}
  ⇒ Δ(t) = (1+t)·Δ₀      （Δ₀ 为 t=0 时的基准差）
  ⇒ Δ(t) 的符号与 Δ₀ 相同，仅在 Δ₀ = 0 时恒为 0
```

**结论（解析）**：`α`、`β` 各 ±50% 时，**符号不翻转；若基准差为 0 则恒为 0**。
⇒ **敏感性在此池上不能提供任何"稳健性"背书**。当 Δ₀ = 0 时，结论应判为**「无证据」**，而**不得**因为"±50% 仍不翻转"就宣称稳健——**0 在任何倍率下都还是 0**。这一条必须写进结果的读法说明，防止自欺。

### 3.5 量纲校验与敏感性（按要求的结构填写，v0.1 定稿）

```
人工分钟数来源：L（文献锚定）+ A（池内计数为实测）+ 自设映射假设（提案级无先例）
换算模型：minutes(s) = α·n_new_entities(s) + β·n_new_relations(s)     （γ 项因池内无文本字段而删除）
系数取值：α = 0.75 分钟/实体, β = 0.63 分钟/关系
         来源：L（Gao et al. 2019 c1=45s / uComp 1.6 relations/min；⚠️ 4 篇文献待实抓核验）
量纲校验：与文献区间对比 → 【落在】合理区间
         α ∈ [0.27, 0.75]、β ∈ [0.42, 0.63]；取上界（专家级）
         ⚠️ v0 的 α=1.0 / β=2.0 落在带外，已按 §3.2 撤回假设并修正
敏感性：α、β 各 ±50% 时，结论【不翻转】；但 Δ₀ = 0 时恒为 0 → 应判「无证据」
        （解析结论，不需蒙特卡洛：Δ(t) = (1+t)·Δ₀，见 §3.4）
```

**唯一豁免**：文献**未覆盖提案级粒度** ⇒ 上述系数是**跨域代理**，不是本项目真值。
⇒ 对外文本必须带此声明（照 `citation-map.md:89`「数字主张标 A/E/L」的纪律，L 级也需标注适用范围）。

### 4.3 【关键推导】排序因子在本池上**结构上无分辨率**

`[代码可读 + 推断]` 逐步推导：

```
可得特征盘点（池内实际字段）：
  confidence : CLS = 1.0 (×10) | Metformin = 0.9 (×1) | REL = None (×10)
  novelty    : 池内不存在（P6 导出 SQL 未取）
  impact     : 池内不存在（同上）
  evidence_spans → build_ev_rich : 恒 0.6（21/21）

臂 A 排序键 = 池内数组序（P6 ITEMS 元组序）
  → [10×CLS] → [10×REL] → [Metformin]           （Metformin 在第 21 位）

臂 B 排序键 = rank_proposals 生产键 = (score_formula, ev_rich) 降序
  score_formula = 0.5·conf + 0.2·novelty + 0.3·impact
  因 novelty = impact 缺失（视为 0），退化为 0.5·conf（单调变换）
  → CLS(0.50) > Metformin(0.45) > REL(0.00)
  → [10×CLS] → [Metformin] → [10×REL]           （Metformin 在第 11 位）

⇒ 两臂序列的差异 = 单个条目 Metformin 的位置（21 ↔ 11）

```

**推论**：

1. **若 Q\* 在前 10 项内达成**（高度可能，见下）→ **两臂累计分钟数恒等**，Δ ≡ 0。
2. **若 Q\* 需超过 10 项** → Δ = `±(β·j − minutes(Metformin))` 量级，即**由单个条目决定**。n=1 的差异**不构成任何证据**。
3. 这正是 `优化-终版 §3.2` 批评 P2 的同一结构病：**设计上期望为 0**。

**为什么 Q\* 极可能在前 10 项内达成** `[推断]`：`Quality(·)` 只看 `classes`；`cls:Metformin` 是**第 11 个类**（若并入），对 `cov`/`align` 的分母贡献 +1/11，对分子贡献取决于其 `parent`/`anchor`（池内未导出，`[未核实]`）。而 10 个 seed 类与 `Metformin` 在 v1.1.0 中**全部并存**（存活代理 20/20 非错）→ 说明**并入与否不改变"非错"判定**，也就很可能不改变四指标。

## 12. 【主理人建议】推荐方案（v0.1 追加，供裁决 D-1 ~ D-4）

### 12.1 核心判断

> **本池上「排序 → 效率」这一因果链在数学上不可测（§4.3 结构零）。**
> 因此**无论怎么调参，任务书原设计都产不出"效率优势"的正面证据**。
> 但「效率」问题本身**没有失败**——它只是**被证据门遮蔽了**。
> ⇒ 建议把本轮目标从「**证明排序有效**」改为「**定位效率瓶颈 + 交付可复用的效率实验协议**」，并**追加一条合成流机制验证**来承载"排序有效"这一命题。

### 12.2 推荐：三件套（甲 + 乙 + 丙）

| 件 | 内容 | 承载的命题 | 证据等级 | 预期结论（**预先写死**） |
|---|---|---|---|---|
| **甲** | **真实池 2×2**（门 开/关 × 排序 到达/score） | 「瓶颈是证据门，不是排序」 | **A**（池为真实产物，as-if 重放） | 门因子：大效应；**排序因子：结构零（Δ=0）** |
| **乙** | **合成异质候选流**（n≥120，gain 与 cost **显式异质**）上的「到达顺序 vs score 排序」分钟数–Quality 曲线 | 「在异质候选流上，score/VOI 排序更早达到 Q\*」 | **合成机制验证**（与 P1/P4 **同级**，**不得**当作真实效率证据） | 排序因子：**有分辨率**，预期 B 更快；**但须接受可能仍无差异** |
| **丙** | **严格版设计**（只出文档，不跑） | 「如何取得 A 级真人计时证据」 | **P**（计划） | 给出 E→A 升级路径 + 扩池前置条件 + power 算术 |

**为什么必须加「乙」**：任务书的原始命题（排序→效率）**只能在一个候选增益异质的流上被检验**。
现池的致命缺陷是**候选的 gain 高度同质**（10 个类≈同一层级、10 个关系对 Quality 完全不可见）⇒ 排序无从发挥。
**合成流恰好可以构造"异质 gain + 异质 cost"**，从而让该命题**可测**——这是 P2 做错的地方（P2 让 `p_confirm` 独立于排序 ⇒ 期望恒为 0，`优化-终版 §3.2` 已批评）。**乙必须避免重蹈**：`gain` 与 `cost` 都必须**依赖候选特征**，且与排序键**相关而非独立**。

> ⚠️ **「乙」的三条硬约束（否则会重演 P2/P4 的病）**：
> ① `gain(s)` **不得**独立于排序键抽取（P2 的病根）；
> ② 必须**包含一个"排序无效"的负对照**（如按 target 字母序）——若负对照也"更早达标"，说明效应来自构造而非排序；
> ③ 产物必须标 `evidence_class: "synthetic_mechanism_validation"`，**禁止**进入对外材料作为效率证据（`citation-map.md:89` 的纪律同样适用于此）。

### 12.3 对 D-1 ~ D-4 的具体裁决建议

| **D-1** | **正式版用 r1，r2 作附注** | L 级只覆盖**系数**，不覆盖「1 提案 = 1 实体/关系」这个**自设映射**；而映射正是本实验的核心粒度，一旦被质疑，整组数字塌掉。**用 L 包装一个自设假设 = 把 E 级风险伪装成 L 级**，比直接用 E 更危险 |

### 13.2 为什么必须改（`Quality(·)` 不可计算，逐条）

| 分量 | 需要字段 | 冻结池是否有 |
|---|---|---|
| `cov` | `seed_terms`（外部注入） | ❌ |
| `red` | `classes[].parent`、`classes[].also_parent` | ❌ |
| `dep` | `classes[].parent` | ❌ |
| `align` | `classes[].anchor` | ❌ |

- 冻结池每项仅 7 字段 `(op, target, confidence, evidence_spans, tenant, gold_error, gold_source)`（`probe_p6_autonomy_tau.py:111-142`）；P6 的 `EXPORT_SQL` 只取其中 4 键。
- 这些字段**确实存在于 DB 的 `applied_ops[].payload`**（`_apply_ops` 把 `CLS_ADD` payload 整包当 class 字典），但**本会话数据库不可达**（无 docker 守护进程，详见 `s1-baseline-readout.md` §1）。
- **退化验证**：若强行只造类名，`Quality` 恒为 `(0.0, 0.0, 1, 0.0)` —— **常数函数**，不是测量。照此出图即"用常数冒充测量"，违反 `AGENTS.md` §0 第 1 条。

### 13.3 修正后的判定标准（**取代 §5.4，两向都写**）

| 判定 | 条件（工作量轴） | 结论措辞（**照抄使用，不得软化**） |
|---|---|---|
| ✅ **支持**「门因子显著降低人审投入」 | `ratio = M_gate_ON / M_gate_OFF > 1` 且差距远超系数敏感性带宽（§3.4） | 「放宽证据门把达到同等本体质量所需的人审项数与人工分钟数按 `ratio` 倍降低（数值见产物 JSON）。**代价**：放行质量风险未量化（P6 裁决金标 `n=0`）。」 |
| ❌ **推翻**（无证据） | `ratio ≤ 1` | 「无证据表明门因子降低人审投入。」 |
| ⚠️ **排序因子** | 预登记零假设：`Δ = M_B − M_A = 0`（门开与门关两态分别检验） | 「排序因子在本池上**结构零**（`Δ = 0`）。该零为**设计必然**（§4.3），非'测不出差异'。」 |
| ⛔ **质量轴** | — | `insufficient_data`：`Quality(·)` 四分量所需字段全缺；解锁前置条件见 §13.2 / `s1-baseline-readout.md` §4。 |
| ⛔ **`Q*`** | — | `insufficient_data`：`Q* ≡ Quality(v1.1.0)` 无法计算。**未用 0 占位**。 |

> **纪律声明**：本节所有阈值与判定规则**在任何实验数字产生之前写定**。上表刻意**不含任何结果数值**——数值只允许出现在产物 JSON 与结论节。
