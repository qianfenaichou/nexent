## 1. Power analysis

### 1.1 预期效应量的**来源**（诚实说明：无empirical来源，改给条件表）

**没有**可引用的实证效应量。可得的三类候选及处置：

| 候选来源 | 是否可用 | 理由 |
|---|---|---|
| 本轮的 `Δ = 0` | ❌ **禁止** | 结构零（§0），非测量 |
| 合成流 ρ 扫描（`probe_p7` 乙部件） | ⚠️ **只能作条件表** | 是**机制验证**，不是经验效应量；但它给出了**效应量随 ρ 的函数关系**，可用于"若 ρ = x，则需 n = y" |
| 外部文献 | ❌ **未找到** | 检索「priority-ordered vs arrival-ordered human review efficiency」未见可比先例（`citation-verification.md`）；原子级本体提案审核耗时本身即零先例 |
| P2 的历史观测 | ❌ **不可用** | `优化-2026-09-23-终版.md` §3.2：P2 的 `p_confirm` 与排序无关 ⇒ **期望净增益恒为 0**，任何正数都是噪声 |

⇒ **设计决定**：本轮**不给单一预期效应量**，而给**以 ρ 为条件的样本量表**（§1.2），
并把「**估计真实 ρ**」列为下一阶段**第一个前置交付物**。这是唯一诚实且可执行的做法。

### 1.2 样本量算术（**完整算术，不省略**）

#### 公式一：均值型终点（「每次接受的分钟数」）

出处：`评审反馈与算法增强路线-2026-09-23.md` §5.4(D)，原式 `n ≈ 16·(1/d²)`。

推导（自洽，便于复核）：
```
双样本 t 检验，双侧 α = 0.05，power = 0.80
  z_{α/2} = 1.96,  z_β = 0.84
  n / arm ≈ 2·(z_{α/2} + z_β)² / d²
         = 2·(1.96 + 0.84)² / d²
         = 2·(2.80)² / d²
         = 2·7.84 / d²
         = 15.68 / d²
         ≈ 16 / d²        ← 与项目既有先例一致，交叉验证通过
```

代入（`d` = Cohen's d，即两臂均值差 / 合并标准差）：

| `d` | 相对降幅（若 CV≈1） | `n` / 臂 = `16/d²` | 算术 |
|---|---|---|---|
| 0.20 | ~20% | **400** | `16/0.04 = 400` |
| **0.30** | ~30% | **178** | `16/0.09 = 177.8` |
| 0.40 | ~40% | **100** | `16/0.16 = 100` |
| 0.50 | ~50% | **64** | `16/0.25 = 64` |

#### 公式二：计数型终点（「接受事件数」）

出处：`agent-statistics-audit.md` §6.3（EFF′ 设计），原式 `N_event = 2·(za+zb)²/δ²`。

```
设每档接受事件数 ~ Poisson(λ)，复核耗时 ~ 指数分布（CV = 1）
  Var(μ) ≈ μ² / N_event,  μ = Σ耗时 / N_accept
  需要 za·√(2μ²/N) + zb·√(2μ²/N) ≈ δ·μ
   → N_event = 2·(za + zb)² / δ²
             = 2·(1.96 + 0.84)² / δ²
             = 2·7.849 / δ²
             = 15.68 / δ²
```

| `δ`（μ 的相对差） | `N_event` / 档 | 算术 | 折算候选数（若过门率 ≈ 1/3） |
|---|---|---|---|
| 0.20 | **392** | `2·7.849/0.04 = 392.5` | ~1180 |
| **0.40** | **98** | `2·7.849/0.16 = 98.1` | ~300 |
| 0.50 | **63** | `2·7.849/0.25 = 62.8` | ~190 |

> 两式在 δ=d 时给出**同一量级**（392 vs 400、98 vs 100），互为交叉验证 ✓

#### 条件表：以 ρ 为参数（用本轮合成流的效应量函数外推）

`probe_p7` 乙部件在合成流（120 候选，20 核心，CV 固定）上给出：
`Δ(ρ) = M_score − M_arrival`，`M_arrival ≈ 79.6 min`（各 ρ 档稳定）。
把 `d ≈ |Δ| / (M_arrival · CV_assumed)`、`CV_assumed = 1` 作**粗估**（⚠️ 合成流 CV 可控而真实未知，故标 `[推断]`）：

| ρ（增益与排序特征的相关性） | 合成 Δ (min) | 相对降幅 | `d` 粗估 | `n`/臂 (`16/d²`) | 判定 |
|---|---|---|---|---|---|
| 0.00 | +1.7 | −2% | ~0.02 | **~40000** | 实际等价于**不可检出** ⇒ 排序无价值 |
| 0.25 | −2.1 | +3% | ~0.03 | **~17800** | 不可行 |
| 0.50 | −24.1 | +30% | ~0.30 | **178** | **可行（本轮建议目标）** |
| 0.75 | −50.9 | +64% | ~0.64 | **39** | 易检出 |
| 1.00 | −64.6 | +81% | ~0.81 | **24** | 易检出 |

**读法（必须写进结论）**：
> 排序的价值**完全由 ρ 决定**。ρ < 0.25 时该命题**在统计上不可救**
> （需 4 位数样本）；ρ ≥ 0.5 时 n = 178/arm 即可（α=0.05, power=0.80）。
> **⇒ 下一阶段的第一件事不是扩池，而是估计 ρ。** 若实测 ρ 很小，
> 应当**放弃"排序提效"这条命题**，把资源移到证据门方向（本轮已证门因子有 2.3× 量级的杠杆）。

### 1.3 分析单位（**任务书 §7.1 要求的说明 + 一处归属纠错**）

| 项 | 本轮（as-if 重放） | 严格版 |
|---|---|---|

#### ⚠️ 纠错：任务书 §7.1 的一处归属错误（已实证）

任务书原文：
> 「说明分析单位：是"**提案**"还是"**轮次**"？（P6 的教训：分析单位选错会虚高精度约 1.7×）」

**「1.7×」不出自 P6，出自 E1。** 原始行（`.workbuddy-tmp/stat_audit_output.txt` §B2）：
```
B2. E1 baseline: 20 questions x 3 runs = 60 judged runs, but only 20
    independent questions (runs are repeated measures on the SAME question).
    MDE vs a 50% baseline at n=20 independent questions:      0.4173
    MDE at n=60 if runs were independent (they are not):      0.2508
    -> the 3x multiplicity of runs inflates apparent n by ~1.7x in MDE terms.
```
核验：`0.4173 / 0.2508 = 1.664 ≈ 1.7×`。
**P6 的池是 21 条不重复候选，没有 run 层重复测量** ⇒ 不存在这个 1.7×。
⇒ **严格版设计中不得把 1.7× 写作"P6 的教训"**。P6 的真实教训是**效度错误**（用 auto-accept 比例当效率指标），不是精度虚高。

**项目内同类先例可直接引用**（`competition/docs/pitfalls.md`）：
- **#47**「度量口径与标注粒度错配」——precision 上界≈1.3% 由粒度决定而非质量；
- **#66**「口径单位错配」——分母 691 条段落级 vs 金标 9 条话题级，不是同一单位。
⇒ 与本实验的「提案级 vs 轮次级」是**同一类错误**，必须显式声明分析单位。

## 2. 扩池方案

### 2.1 需要多少提案

由 §1.2 公式二，以「接受事件数」为准：

| 目标可检出 δ | 需要接受事件 / 档 | 需要提案 / 档（折算） |
|---|---|---|
| 20% | 392 | ~1180 |
| **40%（推荐起步）** | **98** | **~300** |
| 50% | 63 | ~190 |

折算系数说明：`候选数 ≈ 接受事件数 × (1 / 过门率) × (1 / 接受率)`。
本池实测过门率 = **0 / 21**（`ev_rich` 全拒），接受率未知（裁决金标 `n=0`）。
⇒ **折算系数目前无法定值**，上表按"过门率 ≈ 1/3、接受率 ≈ 1"的乐观假设给出，**必须标注为 `[推断]`**。
⇒ **真实所需候选数应在过门率与接受率实测后重算**，这是扩池的**前置步骤**。

## 3. 真人计时的接入方案（**E → A 级升级路径**）

### 3.1 谁审

- **≥ 2 名标注者独立并行**（避免单人偏好无法估计评审者间信度）。
- **每位标注者至少覆盖一部分重叠池**（重叠 ≥ 30%），用于计算 Cohen's κ 或 ICC。
- 标注者需**具备该领域知识**（2 型糖尿病指南）；若不具备，须在限制中声明（领域外标注者耗时偏高，会**高估**人工成本，方向保守，可接受但须声明）。

### 3.2 怎么计时

| 项 | 方案 |
|---|---|
| **计时粒度** | **逐条**（每条提案一个计时区间），不按批次 |
| **三段拆分** | 记录 `阅读耗时` / `判断耗时` / `提交耗时` —— 三段和 = 单条总耗时 |
| **工具** | ① 客户端埋点（工作台按钮级 `mousedown`→`click`）；② 兜底：秒表 + 纸质记录 |
| **数据落点** | 新表或新列，**不得**改写既有迁移（`AGENTS.md` §0 第 2 条 / 任务书 §9 禁改迁移）；建议落 `ontology_change_proposal_t.review_seconds`（**须由接线任务批准**，本会话不擅自加迁移） |
| **记录的字段** | `proposal_id / reviewer_id / t_start / t_end / seconds_total / seconds_read / seconds_judge / seconds_submit / decision(confirm\|reject) / reject_reason` |

### 3.3 如何避免「边审边学」污染（**这是 A 级数据最容易脏的地方**）

| 污染源 | 后果 | 对策 |
|---|---|---|
| **学习效应**（审得越多越快） | 后审的条目耗时系统性偏低 → **混淆排序与熟练度** | ① **随机化审核顺序**（每位标注者的顺序独立随机），使学习效应与排序臂**解耦**；② 记录每位标注者的**序号**，作为协变量 |
| **疲劳效应** | 后审条目变慢 | ① 每 session 上限（如 40 条，与 `MAX_PROPOSALS_PER_SESSION` 对齐）；② 插入**对照项**（同一重复条目）测漂移 |
| **域内先验暴露** | 标注者已读过该指南 → 耗时偏低 | ① 记录"事前是否接触过该域"；② 跨域验证时优先用标注者**不熟悉**的域 |
| **排序臂泄漏** | 标注者猜到分组 | **双盲**：不告知排序规则；两臂条目混合在同一次 session 内交替出现 |
| **人为加速** | 追求快而乱判 | 同时记录 `decision`；用**错放率**（与事后金标比对）做质量护栏 |

### 3.4 ρ 的估计程序（**C-7，最高优先级**）

目标：估计「候选的真实质量增益」与「排序特征」的相关性 ρ。

```
步骤 1  取得候选的**真实增益**（需要金标，故依赖 C-6）
        gain(s) = ΔQuality(本体 ∪ {s}) − Quality(本体)      ← 需要 C-2 才可算
步骤 2  取得候选的**排序特征** score(s) = 0.5·conf + 0.2·novelty + 0.3·impact
步骤 3  计算 Spearman 秩相关 ρ_s(gain, score)
步骤 4  若 ρ_s 显著 > 0 → 排序有前提；用 §1.2 条件表取 n → 进扩池
        若 ρ_s ≈ 0        → **放弃"排序提效"命题**，资源转向证据门方向
步骤 5  ρ_s 的置信区间用 bootstrap（**对候选重抽样**，不伪造重复观测）
```

> ⚠️ 步骤 5 的 bootstrap 是**估计不确定度**，与任务书 §6 禁止的「用重采样把 21 个提案凑成更多独立观测」**性质不同**——前者用于 CI，后者用于伪造 n。此区别必须写进报告，避免被误读为违规。

## 4. 推荐的下一阶段执行顺序

```
P0  C-1 启数据库（用户）
    ↓

    ↓

    ↓

    ↓
P5  3.1–3.2 真人计时（≥2 标注者，双盲，随机序）→ A 级分钟数
    ↓

```

**并行建议**：P4（抽检协议）**不需要改代码、不需要扩池**，只改流程 + 要人审 20–30 条，
