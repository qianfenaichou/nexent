## 0. 项目定位与战略结论（先读这一节）

**项目名**：Nexent-KnowEvo（知识进化引擎）· 赛题3：基于华为 ModelEngine Nexent 打造可进化决策智能体

**一句话战略**：官方"可进化"= **知识体系演进**（本体+图谱随行业标准演进），不是提示词自进化。全项目押注**三个 2024-2026 文献空白点**（见 §3），其余模块以成熟组件集成 + 诚实消融呈现。

### 0.1 关于"缝合性"的诚实裁决（重要）

项目骨架是**对约束的成熟响应**，不是拍脑袋。但架构主干六块（路由/双时轴/增量建图/本体归纳/实体对齐/pass^k）**全部有现成出处**——若评委只数"新模块"，批评成立。**破局点不在换架构，而在把已埋下的三个文献空白点扶正为创新主轴**：

| 空白点 | 文献检索结论（arXiv API 核验，见 04-武器库） | 项目对应 |
|---|---|---|
| **① 指南/标准版本变更 → 图谱受影响面 → 增量更新提案** | "ontology change + impact analysis" **零命中**；GitHub 8 轮检索无成熟实现（最接近者 0★ 且只做定性 diff） | 原 K5（**应从"演示"升格为创新主轴**） |
| **② 版本钉住的多跳推理**（每跳约束到指定版本有效事实） | **无任何先例**；且 2606.26511 刚证明余弦相似度几乎无法区分过期事实（AUROC 0.59） | 原 K2×K3 交叉点（**当前完全未提出**） |
| **③ 人审预算作为本体构建优化目标** | "active learning + ontology" **零命中** | 原 K1 排序公式（**需重述为预算优化**） |

**这三个点正是评审原文点名的"低资源差异化、原创性算法优化方案"。**

### 0.2 三个必须修的真实算法漏洞

1. **实体对齐"二甲双胍=格华止"机制算法上不成立**——generic 与 brand 是"同指异名"，embedding 相似度远达不到 0.85。**必须引入外部标识主键**（ATC 编码/国家医保码/NMPA 本位码）做 blocking + 药品别名表。这是**正确性问题**。
2. **15k token 本体注入是硬编码规模炸弹**——本体长大即被截断，越靠后的文档抽取质量越差。改用**本体子图检索**（Ontology RAG）。
3. **效率对照的人工基线是"稻草人"**（"队员扮演专家"会被击穿）——重述为**"人审预算-质量曲线"**，规避专家基线难题，且命中空白点 ③。

> 详细修法与新增算法（版本钉住形式化、最小充分更新集、冲突消解子系统）见 [02-技术方案](02-技术方案.md)。

## 1. 官方赛题拆解（五条任务 → 五块交付）

> 完整原文见 **附录A**。赛题背景原文：*"医疗、金融、先进制造、政务等行业沉淀海量多模态异构存量数据…行业普遍存在标注稀缺的低资源场景，知识体系更新迭代快，传统固定知识库难以适配动态业务标准。请参赛队伍构建领域资产认知智能体，实现行业数据价值激活与智能化业务编排。"*

| # | 任务要求（原文） | 实质 | 承载模块 |
|---|---|---|---|
| 1 | 多模态异构数据资产认知智能体，统一识别/理解/**资产标识**文本·表格·图文 | 数据摄取与资产化管道 | L1 |
| 2 | **低资源场景领域知识图谱本体半自动化构建**，本体**持续动态更新**，与行业规范/**标准体系对齐** | ★知识图谱本体工程（**算法创新主战场**） | L2 + L4 |
| 3 | 深度集成 Nexent **MCP 协议与 Skills 编排**，打造**「检索-推理」双驱动协同执行流** | 平台深度用（架构主战场） | L3 |
| 4 | 挖掘沉睡存量数据资产，**跨文档多跳推理、决策链路可溯源**；沉淀**可复用 Skill 工作流模板** | 决策溯源 + 能力沉淀 | L3 + L4 |
| 5 | 智能体基于 Nexent 平台可运行 | 硬性运行要求 | L0 |

### 1.1 「可进化」的官方语义（认知锚点，勿再动摇）

- **不是**智能体提示词自进化（Reflexion→GEPA/AFlow 变异）；
- **是**知识体系进化——背景原文点明「传统**固定知识库**难以适配**动态业务标准**」，任务2 要求「本体**持续动态更新**」。华为要的是**知识与能力资产随行业标准演进而演进**。
- 推论：v1 的 L4 进化引擎（prompt 变异、AFlow 工作流搜索）从核心**删除**（保留为 future work 引用）；**本体/图谱版本化演进成为核心**。

### 1.2 「决策」的官方语义

= **跨文档多跳知识推理 + 决策链路可溯源**（任务4 原文），不是通用自主决策探索。**决策卡**（候选方案|证据链|置信度|风险|反事实|知识版本戳）是"决策链路可溯源"的直接载体。

### 1.3 评审规则硬情报（见附录A 全文）

- **初赛 = 100% 技术评分，四维均等 25%**：①编排与 MCP/Skill 深度集成 ②资产激活业务价值 ③**算法创新性（原文点名"低资源差异化原创算法、半自动化本体构建效率优势明显"）** ④交互体验与能力沉淀。
- **中国总决赛 = 技术 60%（四维各15%）+ 答辩 40%（材料 20 + 问答 20）+ 附加 10 分**（多行业模板轻量化迁移 + 真实脱敏数据集评测）。
- **赛题3 止步中国总决赛**；决赛为**线上答辩 15 分钟展示 + 5 分钟问答**。
- **初赛提交物是文档不是代码**：①开发设计文档 Word（项目概述/整体方案设计/**知识图谱构建方案**/智能体构建方案/原始数据说明/数据处理说明）；②Nexent 平台智能体设计思路及**完整配置细节 + 示例问答截图** + json/知识库/MCP 文件说明。**→ 12 月初赛前系统必须在 Nexent 上真实跑通并留截图。**
- **入围决赛必须开源到 GitCode/GitHub**；组委会**复现验证**材料效果；知识产权条款明文"抄袭剽窃自负后果"。
- 晋级名额：54 队晋级中国总决赛（三题合计），赛题3 决赛奖 4/6/8 队。报名截止 2026-11-30。

## 2. 行业与场景选型

| 行业 | 多模态丰富度 | 公开数据可得性 | "本体动态更新"叙事 | 决策溯源故事 | 合规风险 | 附加分迁移容易度 |
|---|---|---|---|---|---|---|
| **医疗** | ★★★ | ★★★ | ★★ | ★★★ | 中 | 中 |
| **政务** | ★★ | ★★★ | ★★★ | ★★ | 低 | ★ |
| 金融 | ★★ | ★★ | ★★ | ★★ | 中高 | 中 |
| 制造 | ★★ | ★ | ★ | ★ | 低 | 难 |

**决策：主场景 = 医疗（2 型糖尿病用药决策子域）；附加分迁移场景 = 政务（政策办事域）**。

- 医疗多模态异构性最强（文本/表格/图文三样全占）、公开资源最丰富、附加分"真实脱敏数据评测"最易兑现；
- 政务做**轻量化迁移验证**（同流水线换语料，出新本体版本+示例问答），命中附加分第一条；
- **域越小越好**（裁决：钉死"2 型糖尿病**用药决策**"子域，不做"全周期诊疗"）——最小可信语料 = 指南 2 版本 + 药品说明书 10 份 + 检验报告 20 份。域小才能把本体做精、溯源链做透。

### 2.1 主场景定义

「2 型糖尿病用药决策认知智能体」——输入：诊疗指南（按版本）、临床路径、药品说明书、检验报告单（表格）、患者教育图文；输出：面向医学生/基层医生的**用药认知辅助决策**，每次回答附完整证据链（文档级+图谱节点级）+ 决策依据卡。
示例决策任务：「该患者糖化 7.8%、eGFR 45、合并 ASCVD，一线用药应如何考量？为什么不用二甲双胍常规剂量？」——需跨指南/说明书/检验多文档多跳推理 + 指南版本演进对比。

## 3. 目标架构：KnowEvo 六层（v3）

> 设计总纲：**底层最大复用 Nexent 原生能力**（评分维度1 要求"深度集成"），**增量全部以"可分离的新目录/新服务/新工具"叠加**（多行业迁移与开源洁净度要求），**绝不侵入式改动上游代码**（保证跟随上游月度发版）。

```
┌──────────────────────────────────────────────────────────────────┐
│ L5 交互与叙事层（前端增量）                                          │
│  资产看板(多模态资产库/标识/血缘) · 本体工作台(本体树/diff/版本时间线) │
│  决策卡面板(证据链展开/溯源跳转) · 评测报告页                          │
├──────────────────────────────────────────────────────────────────┤
│ L4 知识进化与能力沉淀层 ★"可进化"核心（创新主轴）                      │
│  本体版本管理(半自动提案→人工确认→版本化发布/回滚/diff)              │
│  图谱增量更新(新文档→增量抽取→实体对齐合并)                          │
│  【新】标准对齐器(指南新版→变更检测→受影响面分析→最小充分更新集)      │
│  【新】冲突消解(演化/来源差异/抽取错误/同源矛盾的分类裁决)            │
│  Skill 工作流模板库(高频决策链→模板化沉淀→一键复用)                   │
│  经验记忆插件(轻量·差异化·可选)                                     │
├──────────────────────────────────────────────────────────────────┤
│ L3 决策执行层：「检索-推理」双驱动协同执行流 ★评分维度1&2 主战场       │
│  Skill 分层编排: 入口(路由) → 子任务(检索/推理/组装) → 原子 MCP 工具  │
│  ├ 检索驱动: knowledge_base_search(ES混合检索·原生) + kg_search      │
│  ├ 推理驱动: kg_multi_hop(束搜索·【新】版本钉住) + 证据链组装         │
│  决策卡: 候选方案|证据链(EXTRACTED/INFERRED)|置信度|风险|反事实|      │
│          知识版本戳|【新】版本钉住路径|【新】冲突裁决 ← 溯源直接载体   │
├──────────────────────────────────────────────────────────────────┤
│ L2 知识引擎层 ★算法创新主战场                                        │
│  本体半自动构建: 种子(标准目录)→LLM两级提案→校验→人工确认(预算优化)  │
│                  →版本化入库                                        │
│  图谱构建: 本体锚定抽取(【新】子图检索注入) → 三级实体对齐           │
│            (【新】外部主键blocking) → bi-temporal 入图              │
│  双路索引: ES(原生混合检索) + PG JSONB/递归CTE                       │
├──────────────────────────────────────────────────────────────────┤
│ L1 数据资产层（评分维度2：沉睡资产激活）                             │
│  多模态摄取: Nexent 原生 Unstructured 管线 + 表格专项解析 + OCR兜底   │
│  资产标识: 文档分类/元数据抽取/资产编号/来源与版本血缘                │
├──────────────────────────────────────────────────────────────────┤
│ L0 Nexent 原生底座（fork·最小侵入）                                  │
│  FastAPI 5服务 + Next.js 15 + PG/ES/Redis/MinIO + smolagents 内核    │
│  + MCP生态 + Skills + 知识库 + 评测工作台 + 版本管理 + 多租户         │
└──────────────────────────────────────────────────────────────────┘
进化闭环（对齐官方"可进化"语义）:
  行业标准/文档更新 → L1 摄取 → L2 本体/图谱增量演进(版本化)
  → L3 决策引用知识版本戳(版本钉住推理) → L4 沉淀模板
```

### 3.1 v2 → v3 架构差异（本次整合的新增/升格）

| 模块 | 处置 | 理由 |
|---|---|---|
| L4 标准对齐器 | **升格为创新主轴** | 文献空白点①，评审原文点名的"原创算法" |
| L3 版本钉住多跳 | **新增** | 文献空白点②，最干净的空白 |
| L2 人审预算优化 | **新增/重述** | 文献空白点③（原 K1 排序公式的重述） |
| L4 冲突消解 | **新增子系统** | 多版本多来源下冲突是常态，是"可进化"的工程地基 |
| L2 本体子图检索 | **新增** | 解 15k 硬编码规模炸弹 |
| L2 外部主键 blocking | **修正** | 实体对齐正确性 |
| 其余（路由/双时轴/增量建图/pass^k） | **保留** | 成熟组件集成，引用即可 |

### 3.2 关键设计原则（铁律）

1. **最小侵入上游**：新代码全部在自包含目录（`backend/services/knowevo/`、`backend/database/knowevo_db.py`、`mcp_servers/`、`frontend/features/knowevo/`、`competition/`），接线只在少数文件（走接线任务）。
2. **本体是骨架、图谱是血肉、版本是时间轴、决策卡是出口、评测是证据**。
3. **弃用优先于删除**（append-don't-rewrite）——决策卡知识版本戳要能回溯旧版本，物理删除会打断溯源链。
4. **零侵入评测**：自定义指标写成 Nexent 原生 code 评测器（签名 `evaluate(query, expected, actual, runtime_events)` 完全匹配），上游 `evaluator_service.py` 零改动。

## 7. 答辩策略

- **叙事主线**：「沉睡的行业数据 → 认知资产 → 可溯源的决策 → 随标准演进的知识体系」——四段正好对应四个 25% 维度。

- **创新点陈述**（对"缝合"批评的正面回应）：明确讲"我们识别出该方向在 2024-2026 文献中的三个空白，并针对性设计了算法"——引用 arXiv 检索结论（见 04-武器库）。
- **答辩 Q 预案**：本体质量如何保证？幻觉抽取怎么办？多跳推理正确性？换行业要多少工作量？为什么不做模型微调？**与直接 RAG 的差异（消融数据）**？为什么不用 Neo4j/graphiti（选型决策表）？
- **踩坑开场**：每个坑 → 沉淀为机制（表格解析灾难→专项解析器；LLM 抽取不一致→消歧对齐器；"感觉变好了"→评测集与 pass^k）。
- 线上答辩 15+5 分钟：3 分钟价值 + 7 分钟架构与演示 + 3 分钟数据 + 2 分钟沉淀与展望。

### 附录B：Nexent 平台事实（供答辩引用）

- **归属**：Nexent 是华为 ModelEngine 开源项目群（ModelEngine-Group）旗下项目，MIT + 附加条款，仓库 2025-04 创建，2026-09 仍活跃（v2.5.x）。
- **架构**：Next.js 15 前端 + 5 个 FastAPI 服务（config 5010 / runtime 5014 / mcp 5011+5015 / northbound 5013 / data-process 5012）+ PostgreSQL + Elasticsearch（向量+全文混合检索）+ Redis + MinIO + smolagents CodeAgent 内核 + 沙箱。
- **原生能力**：MCP 工具生态、Skill 渐进式披露+沙箱执行、NL2Agent/NL2Skill、A2A 多智能体、三层记忆（Tenant/User/Agent）+ Dreaming、知识溯源（回答附引用）、智能体评估工作台、版本管理与回滚、多租户 RBAC。
- **对接**：可一键同步 ModelEngine 模型与 DataMate 知识库；`MODEL_ENGINE_ENABLED` 开关。
- **工程现实**：Docker 部署 8 核 16G 一条命令；完整 ModelEngine（K8s+gaussdb）有已知坑，需降级方案。
