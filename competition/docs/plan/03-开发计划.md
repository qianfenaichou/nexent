## 2. 硬性代码规范（每个编码任务必须遵守）

1. **上游铁律继承**：分层 = apps 只做解析/鉴权 → services 业务 → database ORM；环境变量**只**在 `backend/consts/const.py` 新增（走接线任务）；SDK 不读环境变量；pytest 不用 unittest；异步测试 `@pytest.mark.asyncio`；**注释/docstring 仅英文**（上游 lint 强制）；行宽 119（ruff）。
2. **前端规范**：Next.js 15 App Router + TS + antd + Tailwind + Zustand + TanStack Query；新页面放 `frontend/features/<域>/`；`npm run check-all` 必须过。
3. **测试即验收**：每个任务简报写明验收命令，**AI 任务没跑过验收命令不算完成**。
4. **反幻觉条款**：开工先读仓库根 `AGENTS.md` 与 `CLAUDE.md`；简报中的文件路径是唯一事实，与仓库实际冲突时停下报告而不是绕过；不得修改"禁改清单"文件；不得发明环境变量；不得引入简报外的重依赖。
5. **Prompt 模板**：一律 YAML 双语成对（`knowevo_xxx_en.yaml`/`_zh.yaml`），格式对齐 `backend/prompts/` 现有模板。

## 3. 并行防冲突机制

### 3.1 文件所有权原则

- **独占文件**：每个任务简报列出"本任务独占的新文件"——只有该任务能创建/修改，零冲突。
- **接线文件（共享，高风险）**：`backend/apps/app_factory.py`、`config_app.py`、`runtime_app.py`（include_router）、`backend/consts/const.py`（新环境变量）、前端路由/菜单注册文件、`pyproject.toml`（新依赖）。
  **规则：接线文件不留给功能任务**——由专门的**接线任务（T-08 系列）**一次性集中完成所有注册/常量/依赖；功能任务只写自包含文件，需要接线时在简报写"待接线项"。
- **上游已有文件**：默认禁改。确需改的（极少）必须走"扩展点改造任务"单独分支并说明 diff 范围。

### 3.2 接线任务清单

| 接线内容 | 归属任务 | 状态 |
|---|---|---|
| `knowevo_db.py` 的 Base 注册进启动导入链、migrate 加载 | T-03 | ✅ |
| 两个新 app 的 `include_router` | T-03 / T-09 | 部分 |
| 新环境变量进 `const.py` | T-03 | ✅ |
| 新 pip 依赖（instructor/fastmcp 等） | 各任务自带，lockfile 合并放 T-08 | 待 |

### 3.3 数据库表所有权

全部新表集中归 **T-03 统一建模**（已按 02 任务书 K 系列产出冻结 schema）：`ontology_version_t` / `ontology_change_proposal_t` / `kg_entity_t` / `kg_relation_t` / `kg_evidence_t` / `kg_pending_entity_t` / `doc_asset_t` / `doc_version_diff_t` / `decision_card_t` / `evolution_round_t` / `skill_template_t` / `eval_run_t`。后续任务只**使用**，不 ALTER（要改=新增迁移文件+新任务简报）。

### 3.4 任务粒度与上下文预算

每个任务 = 一条分支 = 一次 AI 会话可完成；预估超过就拆。判断标准：新文件 ≤8 个、新代码 ≤1200 行、涉及接线文件 ≤2 处。

### 4.2 "重构嵌入"操作规范（合规且干净）

1. **pip/npm 依赖**：直接用，`THIRD_PARTY_NOTICE.md` 登记（名称/license/用途/链接）。
2. **借鉴架构思想**（graphiti 的 bi-temporal 数据模型、graphify 的确定性解析、mattpocock 的 SKILL.md 格式）：**自己写实现**（适配 Nexent 数据模型），在 docstring 与设计文档注明 "Design inspired by X"——学术规范 + 答辩加分。
3. **摘取片段**（τ²-bench 的 pass^k scorer 逻辑）：重写进我们的服务，注释标协议出处（arXiv 号）。
4. **禁止**：直接复制他人仓库文件不带出处；移除上游 LICENSE/NOTICE；把别人代码改名当原创。决赛开源+复现+知识产权三重约束下，**出处清晰才是护甲**。
5. Fork 保留 Nexent 的 LICENSE/NOTICE/AUTHORS 与前端 LOGO。

### 4.3 前端 skills 使用指引

- **产品内动画**：用 `motion`（MIT）——motion-web / animation-vocabulary / find-animation-opportunities skills 的设计原则直接适用。
- **GSAP skills**：留给 PPT 演示动画与答辩视频制作（产品代码统一用 motion，保证开源仓库洁净度）。
- **apple-design / emil-design-eng**：L5 面板视觉打磨阶段（幕3）再调用。
- **code-review / tdd / implement**：每个编码任务收尾时用 code-review skill 自查一轮。

## 5. 质量门禁（Definition of Done）

任务完成的充要条件（简报验收清单逐项打勾）：
1. 新代码全部在简报声明的文件内（接线项除外，已登记待接线清单）；
2. 验收命令通过（pytest 目标文件 / `npm run check-all` / 部署冒烟脚本）；
3. ruff 无告警；注释英文；prompt 模板双语成对；
4. 若建表/改 schema：新迁移文件已加且本地 migrate 通过；
5. 简报末尾"Evidence"节填上测试输出关键行/截图路径/冒烟日志——**没有证据=没做完**；
6. 对应 `competition/docs/pitfalls.md` 补记新踩的坑。

## 8. 调度循环（你只需要做这个）

