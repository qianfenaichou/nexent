## 一、两套口径到底是什么（先定义，再谈优劣）

| | **caliber A：item 级**（旧的「chunk 级」首测） | **caliber B：topic 级**（今回选定为对外口径） |
|---|---|---|
| **比较单位** | 机器产出的**单条变更项** vs 人工金标**话题行** | 把机器项按 `(change_type, 归一化章节)` 折叠成**组**，vs 人工金标**话题** |
| **precision 分子/分母** | 分子 = 机器项中 `(change_type, 归一化锚点)` 与某个金标话题键**完全相等**的条数；分母 = **全部机器项** | 分子 = 与某金标话题匹配上的机器**组**数；分母 = 全部机器**组**数（**下界**，非真 precision——见 §三·3） |
| **recall 分子/分母** | 分子 = 被命中的金标行数；分母 = **可评估**金标行数 | 同左（单位改为话题匹配） |
| **匹配判据** | 锚点字符串精确相等（另有 contains / 同类型 token 重叠两档放宽） | 判别性 token 重叠（CJK 三元组 + ASCII 词，文档频率过滤 `max_df_fraction=0.05`，`min_shared_tokens=2`） |
| **输入规模** | 机器 691 项 / 金标 9 行 | 机器 **517 组**（由 691 项折叠）/ 金标 9 话题 |

**金标（两套共用，同一个文件）**：`competition/corpus/guideline_diff_seed.md`，共 **16 行**，其中 **9 行 `verified`/`corrected` 计入评估**，**7 行 `unverified` 被排除**（id `3,5,8,9,12,14,15`）——**排除项同时不进分子也不进分母**。可评估 9 行按类型 = ADD 4 + UPDATE 5。

## 三、决定与理由

### 1. **为什么必须弃用 item 级作为质量口径——算术证明，不是辩解**

**结构性天花板 = `9/691 = 0.013025`（1.3025%）。**

这台检测器**就算完美**（把 9 个金标话题全部命中），在 item 级口径下 precision 也只有 **1.3%**——因为分母是 **691 条段落级机器项**，而金标是 **9 个话题级条目**，两者**不是同一个单位**。本次实跑 `achieved/ceiling = 0.000000`，即连天花板都没碰到（loose 命中 1 项）。

> **结论：`0.00145` 是「粒度单位错配」的产物，不是抽取质量的度量。**把它当作质量数字引用（无论褒贬）都是错的。
>
> 该上界在归档材料中早有记录（`archive/ai-loop-scratch-2026-09/task_b_status-mission-r1-r26/mission.md:146`：「粒度（691 段落级变更项 vs 9 话题级金标行，precision 上界≈1.3%）」）——**本次探针独立重算得到同一数值 `9/691=1.3025%`，互为交叉验证。**

补充的机器侧质量线索（说明低分也**确有**机器质量成分，不能全推给口径）：691 项中 `structural+table=462 / paragraph=229`；**章节标题解析污染 `add 57/215`、`delete 49/184`**（被当成变更锚点的其实是正文散文）——这是真实缺陷，已在 `03-开发计划.md:193` 如实记为「机器 section 标题受正文污染」。

### 2. **为什么选 topic 级**

- **单位一致**：金标是话题级的（人审 16 条指南变更话题），topic 级口径才在同一单位上比较；
- **可复现且已交叉验证**：本次重算与产物持久化值逐位吻合；且归档材料记录的一次独立评审（双人格子智能体复算）也得到同一组 `9/9`、`64/517`；
- **负向对照通过（特异性证据）**：**14 个无关话题 → 命中话题 0、命中组 0**（`[E] negative control`）——说明匹配不是「随便什么都能匹配上」。

### 3. **必须同时披露的三条硬限制（对外表述不得省略）**

| # | 限制 | 依据 |
|---|---|---|
| ① | **n=9。** 金标仅 9 条可评估话题，`9/9` 的置信区间极宽 → **不得由 `9/9` 反推 precision 高**，也不得宣称「对齐器已达标」 | `[A]` 实跑；`9/9` 本身 |
| ② | **`0.1238` 是下界（lower bound），不是 precision。** 它只说明「机器组里有 64/517 被话题匹配判断为与金标相关」，**不含假阳率** | 产物字段名 `precision_lower_bound`；`[D]` 实跑 |
| ③ | **recall 对匹配阈值敏感：** `min_shared_tokens` 从 2 提到 3，recall 从 `9/9` 掉到 `3/9`（df≤0.05）；df 收到 0.02 且 ms=2 时掉到 `7/9`。故「9/9」是**在该组参数下**的结果，不是参数无关的常数 | `[E]` 扫描表（见 §四） |

### 4. **`05` 母本当前的表述必须改（这是本任务的核心动作）**

`05-计划书-初赛提交版.md` §4.1 现文只有一句目标：

> `P/R 协议：机器输出抽 60 变更判定人工核对，目标 P≥0.90 / R≥0.85（漏检由 source_stale 兜底，不静默错）。`

**风险**：只写目标不写实测，评委追问「实际做到多少」时，唯一可查到的实测数字是 `0.00145`（比目标低三个数量级）。而归档材料早已判定「**P/R 目标 0.9/0.85 在该粒度下不可达，对外材料不得照搬**」（`mission.md:146`）。

**建议替换文本见 §五**（已写好精确的原文/新文对照）。

## 四、稳健性扫描（`[E]` 实跑原样，供质疑时自证）

| df 上限 | min_shared | recall | precision_lower_bound |
|---|---|---|---|
| 0.02 | 2 | 7/9 | 35/517 = 0.067698 |
| 0.02 | 3 | 2/9 | 5/517 = 0.009671 |
| **0.05** | **2** | **9/9** | **64/517 = 0.123791**（= 产物采用的参数） |
| 0.05 | 3 | 3/9 | 11/517 = 0.021277 |
| 0.10 | 2 | 9/9 | 65/517 = 0.125725 |
| 0.10 | 3 | 4/9 | 21/517 = 0.040619 |
| 0.20 | 2 | 9/9 | 65/517 = 0.125725 |
| 0.20 | 3 | 4/9 | 21/517 = 0.040619 |
| 1.00 | 2 | 9/9 | 65/517 = 0.125725 |
| 1.00 | 3 | 5/9 | 27/517 = 0.052224 |

**读法**：df≥0.05 且 `min_shared=2` 时 recall 稳定在 9/9；把判别门槛提到 3 个共享 token 后 recall 崩塌到 3–5/9。**这正是 §三·3 限制③的来源**。
