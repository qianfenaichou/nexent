# 踩坑台账（pitfalls）
> 纪律（01 总计划 §5）：从第一个坑就开始记。格式：现象→定位→根因→修复→沉淀机制。每个坑是 PPT 开场的伏笔，机制是回收。

| # | 日期 | 类别(部署/解析/抽取/图谱/评测) | 现象 | 根因 | 修复 | 沉淀机制 |
|---|------|------|------|------|------|------|
| 1 | 2026-09-13 | 部署 | ES 启动失败（本机未复现，开机值已满足） | vm.max_map_count 需 ≥262144 | sysctl -w vm.max_map_count=262144（本机实测 1048576，免调） | 部署 README 检查清单 |
| 2 | 2026-09-13 | 部署 | 现象：自动化环境跑 deploy.sh 拉镜像走 docker.io 源，国内网络拉取缓慢/超时 | 定位：读 deploy/common/common.sh L8 发现 `DEPLOYMENT_IMAGE_SOURCE_DEFAULT="general"`；非 TTY 环境 TUI 步骤（common.sh L1184 multiselect 等）静默跳过全走默认 | 根因：镜像源默认值为 general，交互式选单在管道/后台环境不可达 | 修复：显式传 `--image-source mainland`（deploy.sh 参数入口 docker/deploy.sh L69）；本次实测 mainland 源（elastic.m.daocloud.io / quay.m.daocloud.io / ccr.ccs.tencentyun.com）全部拉取成功 | 沉淀机制：自动化部署一律显式传 `--image-source`；CI/脚本封装时禁止依赖交互默认值 |
| 3 | 2026-09-13 | 部署 | 现象：`psql -d nexent -c "\dt"` 显示 0 张表，误判迁移失败/suadmin 未建 | 定位：`select schemaname from pg_tables` 发现全部表在 `nexent` schema 下（76 张） | 根因：Nexent 迁移 SQL 显式建 `nexent` schema，psql 默认 search_path 不含它；另 MCP 日志中 `pg_type_typname_nsp_index duplicate key` 为迁移幂等检查的良性输出 | 修复：验证一律加 schema 前缀（`nexent.user_tenant_t`）；判定失败前先看 pg_tables | 沉淀机制：DB 验证命令模板写入任务简报验收命令节 |
| 4 | 2026-09-13 | 部署 | 现象：登录接口试 `/api/v1/auth/login` 404，找不到正确路径 | 定位：grep backend/apps/user_management_app.py L106 `@router.post("/signin")`，前缀 `/user` + app_factory root_path `/api` | 根因：Nexent 登录路由是 `/api/user/signin`，非 Supabase 原生 `/auth/v1/token` | 修复：`POST http://localhost:3000/api/user/signin` 返回 200 + SU 角色 | 沉淀机制：API 探活前先 grep 源码定位路由，不猜 RESTful 惯例 |
| 5 | 2026-09-13 | 部署 | 现象：suadmin 登录后访问 /models 被弹"无权限访问"并重定向回首页 | 定位：查 nexent.role_permission_t，SU 的 LEFT_NAV_MENU 权限只有 /、/owner-manage、/resource-manage、/space 四条，无 /models | 根因：Nexent 是多租户架构，SU 是平台超管（管租户/配额），模型配置是租户级页面（ADMIN/SPEED/DEV/USER 才有 /models）；模型注册前必须先建租户+租户管理员 | 修复：suadmin 建租户 knowevo → 生成 ADMIN_INVITE 邀请码 → 注册 admin@knowevo.com（ADMIN）→ 用它登录配模型 | 沉淀机制：多租户平台的"超管≠业务管理员"，初始化流程=建租户→建管理员→再配业务资源；写进部署 README |
| 6 | 2026-09-13 | 部署 | 现象：创建租户时勾选"立即生成租户管理员账户"填 admin@knowevo.local，提示"租户已创建"但"创建租户管理员账户失败" | 定位：config 日志 `POST /api/user/signup 422`；容器内 email_validator 验证 `admin@knowevo.local` → "special-use or reserved name"（.local 是 RFC6761 保留域） | 根因：pydantic EmailStr 内嵌 email_validator，保留域名（.local/.test 等）在请求体校验层直接 422，但前端把 422 显示为通用失败，租户却已创建，状态半成品 | 修复：邀请码 HCIAQP 仍有效，改用 admin@knowevo.com 调 signup API 完成 ADMIN 注册（200）| 沉淀机制：测试环境邮箱一律用 .com/.net 等真实 TLD，不用 .local/.test；前端 422 错误提示不具体时直接看后端日志 |
